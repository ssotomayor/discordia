## 3. Findings — documentation against code

### F-01 — The roadmap defers a feature that has shipped

```text
Severity:    High (for a documentation finding)
Status:      FIXED in this pass
Area:        Docs · roadmap
Confidence:  High
```

**Evidence.** `docs/ROADMAP.md:332` listed `E2EE DMs (NIP-44)` under
"Explicitly deferred". `client/src/nostr/nip44.rs` is 519 lines of shipped
implementation, checked against the specification's own test vectors
(`client/src/nostr/nip44.vectors.json`, committed as a fixture), and
`cargo test --workspace` runs them.

**Why it matters more than a stale line.** The roadmap is the document the
project points contributors at for "what is not built yet." A reader deciding
what to work on would have found the highest-value privacy feature in the
project listed as available. The last audit's A-03 was the same shape — the
roadmap describing a system that did not exist — in the opposite direction.

```text
Severity:    Medium
Status:      FIXED in this pass
Area:        Docs · agent orientation
```

**Evidence.** `diff AGENTS.md CLAUDE.md` → 253 differing lines. The two share a

**Fix.** Rebuilt as `CLAUDE.md` plus its own "How to Contribute" section; the
shared body is now byte-identical, which is verifiable in one `diff` rather

## 5. What is verified, and what is still only reasoned

The suite is green and the gates are clean, which is worth less than it sounds
unless the boundary is stated:

**Verified by executed tests.** The wire protocol end to end (the integration
suites drive a real gateway through the bot SDK), permissions and owner
controls (22 tests), voice token minting including a scripted per-request
failure, guild export/import, persistence across a restart, the rendezvous
handshake, NIP-44 against the specification's published vectors, and the
routing table's non-member exclusion.

**Not verified anywhere, and the list has not moved:**

- **No Nostr DM path has ever run against a real relay.** The commit that
  shipped it says so in its last line. The tests cover the crypto and the
  event construction; nothing covers a live `wss://` relay accepting, storing
  and returning a gift-wrapped event.
- **Nothing has run between two machines.** The QUIC tests run both ends in one
  process over loopback, which settles the plumbing and nothing about NATs,
  advertised addresses, or whether a remote joiner lands on the private path.
- **No port mapping has been observed on a real router** in CI.
- The 9 ignored tests (live SFU, Windows loopback capture, macOS screen
  capture) need hardware no runner has. The Windows one found a heap corruption
  in shipped code the first time a human ran it, which is the argument for
  running them by hand periodically rather than treating them as decoration.

## 8. Deferred-work register

The successor to `TODO.md`, recovered in full from `git show 686808a^:TODO.md`
(851 lines, 68 entries) and re-checked against the tree at `54d6175`. Section
names are kept verbatim, because ~33 source comments cite them ("see … under
Voice / audio") and those citations now resolve here.

Scope is unchanged from the original: *things we know we want but chose not to
ship in the commit that surfaced them.* Reasoning that took a measurement to
establish is not repeated here — where an entry says a thing was measured, the
measurement is in the git history of the file it names.

**Status key.** **Open** — verified still open today, check named. **Unblocked**
— open, and a dependency that was holding it has since landed. **Partly
closed** — some of what the entry asked for has shipped. **Unverified here** —
a product, ops or hardware question this host cannot settle.

### Project

1. **No `LICENSE` file.** Defaults to all rights reserved, contradicting the
   contributing sections. A decision for both copyright holders, not a code
   change; interacts with whether licence exceptions are ever sold (that needs a
   CLA before the first outside PR). — **Open** (`ls LICENSE*` → absent)

### Discordia design adoption

2. **Deferred decorative elements from the comps.** Day-streak, "Send a tip",
   "Relay op", org-"Verified" badges have no backend. — **Open**
3. **The palette icon is not where the comp puts it.** The comp puts it in the
   top bar; `AppearanceButton` renders from `UserPanel` at the sidebar bottom.
   — **Open**
4. **Level curve tuning.** — **Unverified here** (a product call)

### Security

5. **A username may contain control characters, and nothing strips them.**
   `canonical_username` trims and truncates; it does not filter control
   characters, and the same is true of guild/channel names. — **Open**
6. **The gateway is plaintext, and `wss://` looks supported without being.**
   — **Partly closed.** The `wss://` half is fixed: `Cargo.toml:24` now builds
   `tokio-tungstenite` with `rustls-tls-webpki-roots` (added for Nostr relays),
   so a `wss://` URL connects instead of failing after `net.rs` normalises into
   it. The gateway also gained an encrypted, key-authenticated front door in
   `server/src/quic.rs`. What remains: the plain TCP listener still serves
   cleartext, so this is a deployment question rather than an impossibility.

### Repo & CI

7. **macOS clippy gates one profile of two.** — **Open**
8. **The Windows portable and setup ship the wrong icon.** Reported from a real
   download. — **Unverified here**
9. **Windows SmartScreen blocks the download as an unknown publisher.** —
   **Unverified here** (needs a signing certificate decision)
10. **The macOS build is not notarised**, so a recipient has to defeat
    Gatekeeper. — **Unverified here**
11. **`Discordia.html` should be named and moved, not deleted** — it is the
    design source. — **Open** (still at the repo root)

### Assets

12. **The `.icns` is downscaled from the PNG, not rasterised from the SVG.** —
    **Open**

### Persistence & deploy (roadmap P1/P2 leftovers)

13. **Blob GC.** Media blobs are content-addressed and shared, so deletion needs
    refcounting; nothing reclaims them. — **Open** (no refcount in `media.rs` /
    `state/mod.rs`; both comments now point here)
14. **Roster paging.** — **Open**
15. **Docker image untested.** `Dockerfile` and `docker-compose.yml` exist; that
    they build and run is what is unverified. — **Unverified here**
16. **Postgres backend.** `store.rs` is SQLite-only by construction. — **Open**

### Guild owner controls (roles, membership, moderation)

17. **LiveKit force-eviction on kick.** A kicked client is told to hang up, but a
    malicious one keeps a valid token until TTL. Needs `RemoveParticipant` or
    short TTLs. — **Open**
18. **Operator UX polish.** No visual distinction between a system-guild operator
    and an owner, and no in-app view of the operator list. — **Open**
19. **Invite expiry / use limits.** One rotating code per guild; no TTL, no
    max-uses, no per-code attribution. — **Open** (no `max_uses`/`expires_at` on
    the wire)
20. **A reorder can be silently half-applied, and the client cannot tell.** The
    `UpdateChannel` arm drops rate-limited excess with `continue` and no
    `Error`, unlike the arms around it, so the list is left visibly
    half-reordered. Fuel was reduced (a one-slot move costs two messages) but a
    guild that has never been reordered still renumbers every row.
    — **Unblocked.** The entry defers the real fix because
    `server/src/gateway/connection.rs` was being rewritten on the
    `networking-direct-and-private` branch. **That branch merged as #76**; the
    file is stable and the fix — an error on rejection, which makes *every*
    silent rate-limit drop visible — is now reachable.
21. **A reorder writes back a stale snapshot of every row it renumbers.**
    `UpdateChannel` is a full replace, so a concurrent edit to `name`/`topic`/
    `read_only`/`slowmode_secs` on a renumbered row is overwritten by a client
    that did not intend to touch it. Needs a position-only message (a protocol
    change) or a read-modify-write against fresher state. — **Open**
22. **Nobody has performed the channel-reorder *drag*.** The menu path has eight
    unit tests; press-drag-release has none, and two things could stop it that
    the menu path never touches (`prevent_default` timing on `ondragover`, and
    `ondragstart` never calling `dataTransfer.setData`). — **Open**
23. **`MentionEveryone` permission.** Cut from v1 — mentions are computed
    client-side, so the server cannot enforce it without rewriting content. —
    **Open** (zero occurrences in `protocol/`, `server/`)
24. **Role hierarchy / channel permission overwrites.** v1 uses the flat
    grant-subset rule. — **Open**

### Platform — bots (Tier 1) & activities (Tier 3)

25. **Privileged intents have a confirm step, not a verification flow.** The
    confirm step shipped; there is still no review, no scale threshold, and
    nothing stopping an owner granting intents to any key. — **Partly closed**
26. **Bot identity refresh.** A bot's self-declared username is never reconciled
    with the installer-chosen label. Decide which wins and document it. — **Open**
27. **Activity remote URLs.** Needs a CSP story, an allowlist mechanism and
    per-origin capability grants before arbitrary remote activities load. — **Open**
28. **Per-call activity consent.** `message.send` is granted wholesale at launch.
    — **Open**
29. **Activity channel binding.** `message.send` posts to whatever channel is
    selected when the call fires, not the one the activity launched from. — **Open**

### Decentralization / rendezvous

30. **The macOS local-network grant is declared but never exercised.**
    `NSLocalNetworkUsageDescription` was added prophylactically; the path that
    would prove it (LAN self-host from a *bundled* app, friend joining) has not
    been run. — **Open**
31. **Reservation display fields are persisted but never read.** `relay.rs`
    touches only `owner_pubkey`, via `reservation_owner()`. — **Open** (verified:
    that is still the only field read)
32. **A relay older than `can_publish` still grants publish, and nothing detects
    it.** The field defaults to `true` on the relay so older *hosts* keep
    working; the mirror is that an older *relay* silently signs publish. Closing
    it properly means versioning the rendezvous protocol. — **Open**
33. **Name release / rename.** Reservations are sticky once claimed; no
    owner-authenticated unclaim/rename. — **Open** (no such op on the wire)
34. **Signed "guild moved" redirect.** After an export/import migration old
    members still point at the source instance (roadmap P6 tail). — **Open**

### Payments

35. **Zaps are not wired end to end.** "Send a tip" is a placeholder; the decided
    design (NIP-47 + LNURL, no custody) is in `docs/ROADMAP.md`. — **Open**

### Client UX

36. **The Windows client is a console application, so every release ships a `cmd`
    window beside it.** Nothing sets `windows_subsystem`, so the binary is
    `IMAGE_SUBSYSTEM_WINDOWS_CUI` and one-click self-host fills the window with
    the bundled SFU's logs. **The two halves must land together** —
    `windows_subsystem = "windows"` alone gives `livekit-server` a *fresh* stray
    console, so it needs `CREATE_NO_WINDOW` and piped stdio on that spawn. What
    makes it more than two flags is that the console is the only diagnostic
    channel a release build has (`dlog!` compiles to nothing in release, on
    purpose), so closing this means deciding what replaces it. — **Open**
    (`git grep windows_subsystem` → only a forward-looking comment).
    *Count drifted:* the entry cites 96 client console writes (92 `eprintln!` +
    4 `println!`, 66 in `features::voice`). Today: **127 + 12 = 139, with 73 in
    `features::voice`.** The problem it describes got bigger, not smaller.
37. **The fade-in never re-triggers on the connect and identity-setup panels.**
    `rsx!` represents a key only on the **root** node of a body, so a nested key
    is dropped — measured against dioxus 0.7.10 with a four-case probe. The dead
    attributes are gone; restoring the re-trigger means putting the key on a body
    root, and it is not yet established that a changed key remounts a single
    non-list child rather than diffing in place. — **Open**
38. **Live-session username rename.** Takes effect only on the next Connect;
    needs `ClientMessage::UpdateUsername` plus a server-side member-row mutation.
    — **Open** (no such message on the wire)

### Camera / video

39. **`ClientMessage::SetScreenShare` still carries a `channel_id` nothing
    reads.** Kept for wire compatibility with older clients; removable once none
    are expected, which nothing here can detect. — **Open**
    (`connection.rs:770` still destructures `channel_id: _`)
40. **`ScreenShareState` is now redundant for current clients.** Still sent,
    derived from `screen_sharing`, so an older client keeps its LIVE badge. —
    **Open**

### Voice / audio

60. **"Bypass system audio processing" reports that raw mode was *asked for*, not
    that the driver's effects are gone.** WASAPI offers no read-back.
    **First measurement is a stronger negative than expected:** on this host's
    default capture device the raw and non-raw paths came back **bit-identical**
    — 0 of 576,000 overlapping samples differ. Two readings survive that and this
    run cannot separate them (the flag is accepted and ignored, or this endpoint
    has no effects chain). Separating them needs a device known to process and
    actual speech. — **Open**
61. **The raw path is Windows-only and Linux is not answered.** macOS is
    genuinely nothing-to-do; Linux is not — PipeWire/PulseAudio routinely put
    `echo-cancel`/`rnnoise` in front of a source, and nobody has run this repo's
    voice path on Linux. — **Open**
62. **The 30-vs-12 dB ceiling numbers still cannot be re-run.** DeepFilterNet is
    in the sweep now, which **settles** that the ceiling reaches the model and is
    applied to within hundredths of a dB, and **refuses** the comparison the
    entry is about: applied = ceiling means the model is saturated on a signal it
    hears no speech in. What is left is narrow and concrete — a speech-like
    excitation, not another knob. — **Partly closed**
63. **The default mic sensitivity cuts ordinary speech.** The gate opens at
    −26.0 dBFS; reproduced on a two-machine LAN call and measured through the
    outbound packet rate. **Do not just lower the number** — the default assumed
    AGC lifts quiet speech over it, and entry 64 finds that AGC inert, so settle
    that first. **Already ruled out by measurement, do not retry:** exposing
    DeepFilterNet's `ATTEN_LIM_DB`. — **Open**
64. **libwebrtc's noise suppressor may not run at all**, which would make
    DeepFilterNet-off suppressor-*none*. Eight runs put the effect at +0.0004
    with the sign flipping, against an instrument that resolves an effect ten
    times smaller. Half is settled — the options do arrive
    (`the_apm_options_survive_the_round_trip_into_the_source`) — leaving
    stored-and-not-acted-on inside libwebrtc. It matters because it is the
    **default** arrangement. **Do not close this on either check alone.** — **Open**
65. **The transmit gate judges the denoised hop**, so its operating point moves
    when suppression is toggled. The ordering is deliberate: gating the raw
    signal would let a fan the model removes hold the gate open. The alternative
    is a threshold re-derived when suppression changes. — **Open by decision**
66. **Call audio degrades during a screen share, and nothing explains it.**
    Reported by a user. `c6cb994` measured the obvious suspect, found it too
    small, fixed it anyway and wrote "That is still open" — and nothing has
    looked since. The `dlog!` trace points from that investigation are still in
    place; use them. — **Open** (this is the entry that motivated the tracking
    convention in `CLAUDE.md`)
67. **An old client that mutes reads as deafened.** Half the gap closed:
    `Identify` now carries `client_version` and such a client is identifiable by
    *absence*. What is missing is anything that could act on it — the field is
    self-declared and unauthenticated, so it can inform a decision, not gate a
    peer. — **Partly closed**
68. **Two app instances self-hosting on one machine fight over the SFU.** The

    was already broken (fixed port, temp dir and generated config); it now fails
    differently rather than newly. — **Open**
69. **Per-user volumes are session-scoped.** Persisting needs a keyed store that
    does not grow without bound (cap + LRU). — **Open**

## 9. Method notes

Recorded because an audit that hides its own missteps is asking to be trusted
rather than checked.

- **Two counts in §6 were wrong before they were right.** `git grep -o
  "println!"` also matches `eprintln!`, which inflated the count by exactly the
  `eprintln!` total; and an unquoted shell glob (`client/src/*.rs`) is expanded
  by the shell, which does not cross `/`, so it silently missed every
  subdirectory — `features/`, `sysaudio/`, `nostr/`. The figures in §6 use
  quoted git pathspecs and word-bounded patterns. Both errors made the tree look
  *quieter* than it is.
- **The suite was first run through `| tail -60`**, which discarded 16 of the 17
  per-suite result lines and would have supported a confident, wrong sentence
  about coverage. §1 is from a full capture.
- **How §8 was built, exactly.** A local model digested the recovered
  `TODO.md` section by section under a forced schema; it completed **8 of 15
  sections (29 of 68 entries)** before the wall-clock cost stopped being worth
  it, and the remaining seven sections were read and written by hand. The 29 it
  produced were used as a cross-check rather than as copy: per-section entry
  counts match the bullet counts exactly, and all 29 titles match the
  hand-written register in the same order. **No status verdict in §8 is the
  model's** — each was checked against the code, file or command the entry
  names, and the ones this host cannot settle are marked *Unverified here*
  rather than guessed.
